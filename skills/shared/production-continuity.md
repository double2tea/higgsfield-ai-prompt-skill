# Production Continuity — Project-Derived Prompt Craft

`[EMPIRICAL — 本地 LibTV 画布学习，1 项目，2026-10-03；原始记录留在本地]`

来源包含 74 个非空图片提示词节点、432 个非空视频提示词节点，分别有 64、319 条
不重复文本；另有 78 对带源节点关联的草稿／正片记录。本次抽查了 3 个视频的媒体
元数据和 3 张采样画面。重复节点、当前节点字段和静帧都不能证明完整成片的成功率，
以下是可借用的写法与核对方法，不是模型效果保证。公开参考不收录原项目的剧情、
对白、完整提示词或素材地址。

仅在多镜头连续性、片段接续、道具变化或明确的局部缺陷需要处理时加载。沿用用户
选定的叙事与执行方式；不因此增加情绪、剪切、草稿、批量或付费重试，不改写已批准
的执行提示词。

## 1. 素材职责要落到真实绑定

继续使用已有的“采用什么／排除什么”与保真等级，不靠文件名或上传顺序猜角色。

- **结构素材**只提供布局、物体结构或玻璃等光学关系时，明确排除素材中的人物、
  板式或占位背景。若素材有绿幕而成片没有，排除的是绿色背景，不是玻璃本身。
  绿幕不是通用默认流程。
- **声音素材**只提供声线时，不继承原句、配乐或全部场景声；人物外貌由对应图像
  决定。需要原句或原始声景时，则保留用户选择的继承范围。
- **同一物体的多视图**先说明物体数量，再说明每张图代表的视角或表面。两张正反面
  素材不等于两个道具。

LibTV 来源中，195 条不重复视频提示词使用 `{{Mixed N}}`，也有 `{{Image N}}` 和
`{{SegmentRange:…}}`。这些是该平台的绑定语法，不据此评价哪种写法效果更好。
保留已批准文本、实际素材顺序及执行器生成的标签；不要改成 Higgsfield 的 `@Image 1`，
也不要把 Higgsfield 的 house convention 当作其他平台的标签禁令。迁移时先让目标
执行器核对素材映射，未核对前不宣称跨平台可直接执行。

## 2. 交接记录保存状态，执行提示词只写必要变化

在已有分镜或项目记录中，只记该片段真正可能出错的状态，不新建重复的制作日志：

| 检查对象 | 需要交接时记录什么 |
|---|---|
| 人物 | 位置、朝向、视线目标、动作进行到哪一步 |
| 道具 | 数量、持有人、左右手、正反面、是否收起、显示内容 |
| 空间 | 真实距离、车辆运动、门窗状态、前后排或左右位置 |
| 摄影 | 机位、运动阶段、焦点主体、遮挡物及方向 |
| 声音 | 台词是否说完、可见／画外声源、持续环境声 |
| 叙事 | 已完成的事件、必须留给下一片段的事件 |

已接受的源视频携带可见和动态状态，执行提示词主要写下一步变化；这张表是规划与
核对工具，不要求全文重复进提示词。只用静帧接续时，补足它无法携带的运动方向、
摄影运动阶段与声音进度，沿用 Source-carries-state rule。

连续接续要对上源片尾态；明确的时间跳切可重新建立空间。不要把上一段已握住的
道具重新放回桌上取一次，也不要在第一段提前完成后段才需要发生的离场或告别。

## 3. 世界位置、画面方向与光源分别描述

- 区分人物／车辆的真实左右与画面左右。前后排、驾驶位、门窗位置要属于同一空间；
  正反打再分别写画面位置和视线方向，避免换机位后人物互换。
- 长焦近景不改变人物的真实距离。需要远距离正反打时，背景、视线与声音距离仍要
  对得上；不要因为切近景就让两人变成近距离面对面。
- 窗户或灯的位置固定在场景里，换机位后脸上受光侧可能变化。不要要求每个角度都
  维持同一画面侧的高光，导致世界光源跟着摄影机移动。
- 遮挡来自真实物体和开口：窗框、车体、前景行人可以间歇挡住远处主体；不能为了
  看清主体让整面墙或车体透明。情绪需要可读时，把焦点放在实际承担表演的主体上。

空间复杂或已有轴线错误时才补调度图；简单镜头用明确的位置关系即可。

## 4. 双面道具是一件有厚度的物体

先绑定“同一件物体的 A 面／B 面”，再描述有方向的翻转过程：A 面 → 边缘 → B 面。
厚度、折痕、边缘与持握点属于同一物体；避免两面融成一面、变成两件物体，或文字
穿透到背面。示例仅展示关系，素材编号由执行器绑定：

```text
素材 A 和素材 B 是同一张卡片的正面与背面，全程只有一张卡片。
人物捏住右下角向外翻转，卡片先侧向露出边缘，再露出背面；持握点保持连续。
```

仅在该风险实际存在时补这些约束，不机械追加长串否定词。风吹、惯性或接触动作
应写清原因、受力与结果，但文字约束不保证模型能精确完成物理过程。

## 5. 变化需要过程和落幅时间

继续采用已有的阶段、主事件与终态结构，不复制来源项目的固定秒数或镜头数量。

- 时长预算包括动作发生、可见反应和结果停留；需要“离场之后的余韵”时，人物离开
  不是自动结束点。先明确终态要让观众读懂什么，再分配过程和停留时间。
- **选择性时间压缩**要指出谁在加速变化、谁保持正常速度。比如只让某个物体风化，
  周围车辆、行人和光照仍按场景要求运动；保持该物体的连续身份，不偷换成另一件。
- 关注 → 反应 → 终态可帮助描述一段具体表演；静止、无反应或省略过程也可以是用户
  的选择，不把这套关系强制套进所有镜头。
- 背景人物有各自的轨迹，不因主角反应同时停下或集体回头。持续环境声不随一次
  近景无故静音；画外声仍受真实距离与声源位置约束。

来源中的无配乐、硬切、长镜头和特定年代是作品选择，不是本 skill 的新默认值。

## 6. 草稿、正片与超分是不同的生成操作

观察到的 78 对关联记录采用 480p 草稿设置和 1080p 正片设置。这只能证明该项目保存
了这条工作关系，不能证明所有草稿获批、正片完全一致，或默认应该先做草稿。

用户选中草稿后，若该平台支持从草稿生成正片，保留选中版本的素材映射、参数和源
任务关联；不要另建无关联任务冒充同一草稿的正片。当前节点中的可编辑文本不一定
等于历史提交文本，提交收据和选中版本才是核对依据。

正片生成、重新生成和超分按用户要求与执行器能力区分：只要超分时，不强制再进行
一次创作生成。费用与提交授权继续由选定执行器处理。

**编排长度不等于模型单次上限。** 来源保存了 60／80 秒等长视频编排字段；不能把
它们当作模型原生时长。核对当前执行器的单段能力、片段关系与实际媒体时长。

**请求配置不等于交付规格。** 一份抽查记录保存了 1080p 设置，实际媒体为 816×350；
另一份实际媒体为 2206×946。标题、设置和“正片”字样不能替代产物核对。按交付要求
检查实际宽高、时长与音轨；提示词里的 `8K`、帧率或宽银幕风格也不等于参数已经生效。
未说明含义的 schema 值（如 `maxLength: 0`）不解释成无限输入。

## 7. 局部修复只解决明确缺陷

沿用编辑母版、修改范围与时间线继承规则。只改一个显示数字、道具表面或指定区间
时，绑定源视频、实际范围和必要的目标参考，不重写整段故事或人物表演。

由当前执行器获取 `{{SegmentRange:…}}` 等选择标签；不复制其他任务的 ID，不虚构
范围。交付时核对范围前后接缝、遮挡关系与声音，以及用户要求保留的区域是否真的
保留。提示词中的“其他全部不变”是目标，不是产物已达到像素一致的证据。
